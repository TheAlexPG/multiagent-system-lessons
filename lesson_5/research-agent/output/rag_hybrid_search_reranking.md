# RAG, Підходи до Retrieval та Hybrid Search з Reranking

## Вступ

Retrieval-Augmented Generation (RAG) — це техніка, яка дозволяє великим мовним моделям (LLM) отримувати та інтегрувати нову інформацію з зовнішніх джерел даних. Замість того, щоб покладатися лише на знання, закладені під час навчання, RAG-системи спочатку звертаються до набору документів, а потім відповідають на запити користувача. Цей підхід дозволяє LLM використовувати специфічні для предметної області та/або оновлені дані [KB: retrieval-augmented-generation.pdf].

## Що таке RAG?

RAG (Retrieval-Augmented Generation) — це архітектура, яка поєднує механізм інформаційного пошуку з генерацією тексту. Основні компоненти:
- **Ретрівер (Retriever)**: шукає релевантні документи у базі знань на основі запиту користувача.
- **Генератор (Generator)**: LLM, яка використовує знайдені документи для формування відповіді.

Переваги RAG:
- Доступ до актуальної інформації, якої немає в навчальних даних LLM.
- Зменшення галюцинацій завдяки опорі на конкретні джерела.
- Можливість використання приватних або специфічних для предметної області даних [KB: retrieval-augmented-generation.pdf].

## Підходи до Retrieval у RAG

Існує кілька основних підходів до ретрівалу в системах RAG:

### 1. **Naive Chunking (Просте розбиття на чанки)**
- Документи розбиваються на фіксовані розміри чанків.
- Простий у реалізації, але може втрачати контекст.

### 2. **Sentence Window Retrieval**
- Зберігається не тільки сам чанк, а й інформація про його "вікно" (сусідні речення).
- Допомагає зберегти контекст при пошуку.

### 3. **Parent-Child Retrieval**
- Використовує ієрархію: дрібні чанки для точного пошуку, більші "родительські" чанки для контексту.
- Забезпечує баланс між точністю та контекстом.

### 4. **Hybrid Search (Гібридний пошук)**
- Поєднує семантичний пошук (vector search) та ключовий пошук (BM25).
- Семантичний пошук знаходить схожі за змістом документи.
- Ключовий пошук знаходить документи з точними відповідниками слів запиту.
- Це покращує загальну ефективність, оскільки кожен метод компенсує слабкі сторони іншого [KB: retrieval-augmented-generation.pdf].

### 5. **Query Transformation**
- Перетворення запиту для кращого пошуку (наприклад, розширення запиту, переформулювання).
- Допомагає подолати різницю між мовою користувача та мовою документів.

## Hybrid Search з Reranking

### Як працює Hybrid Search?

Гібридний пошук поєднує два підходи:
1. **Векторний пошук (Semantic/Vector Search)**: використовує ембеддинги для знаходження документів, схожих за змістом.
2. **Ключовий пошук (Keyword/BM25 Search)**: використовує статистичні методи для знаходження документів з точними відповідниками слів запиту.

**Процес Hybrid Search**:
1. Виконується два окремих пошуки: один за векторами, інший за ключовими словами.
2. Результати об'єднуються за допомогою методу **RRF (Reciprocal Rank Fusion)**.
3. RRF присвоює кожному документу рейтинг на основі його позиції в обох списках результатів.

**Формула RRF**:
```
RRF score = Σ(1 / (k + rank))
```
де `k` — константа (зазвичай 60), `rank` — позиція документа у списку результатів.

### Роль Reranking

Після Hybrid Search часто застосовується **reranking** для подальшого уточнення результатів:

1. **Cross-Encoder Reranking**:
   - Cross-encoder моделі оцінюють релевантність пари (запит, документ) разом, а не окремо.
   - Це дозволяє врахувати взаємодію між словами запиту та документа на глибшому рівні.
   - Зазвичай використовується після Hybrid Search для фінального ранжування топ-к результатів.

2. **Процес Reranking**:
   - Отримані з Hybrid Search результати (зазвичай 50-100 документів) передаються cross-encoder моделі.
   - Модель присвоює кожному документу новий рейтинг на основі глибшого аналізу.
   - Топ-N результатів (наприклад, 5-10) використовуються для генерації відповіді LLM.

### Переваги Hybrid Search з Reranking

- **Більша точність**: комбінує сильні сторони векторного та ключового пошуку.
- **Краща релевантність**: reranking дозволяє відібрати найрелевантніші документи для LLM.
- **Гнучкість**: можна налаштувати ваги між векторним та ключовим пошуком.

## Порівняльна таблиця підходів до RAG Retrieval

| Підхід | Опис | Переваги | Недоліки |
|--------|------|----------|----------|
| **Naive Chunking** | Просте розбиття на фіксовані чанки | Простота реалізації | Втрата контексту, низька точність |
| **Sentence Window** | Збереження сусідніх речень | Кращий контекст | Більше пам'яті |
| **Parent-Child** | Ієрархія чанків | Баланс між точністю та контекстом | Складніша реалізація |
| **Hybrid Search** | Поєднання векторного та ключового пошуку | Висока точність, гнучкість | Складніше налаштування |
| **Hybrid + Reranking** | Hybrid з подальшим cross-encoder ранжуванням | Найвища релевантність результатів | Вищі обчислювальні витрати |

## Висновки

1. **RAG** — це потужна техніка, яка дозволяє LLM отримувати доступ до актуальної інформації ззовні.
2. **Підходи до ретрівалу** варіюються від простих (naive chunking) до складних (hybrid search + reranking).
3. **Hybrid Search** поєднує векторний та ключовий пошук для кращої покриття різних типів запитів.
4. **Reranking з cross-encoder** дозволяє подальше уточнення результатів, забезпечуючи найрелевантніші документи для LLM.
5. Вибір підходу залежить від конкретних вимог до точності, швидкості та обчислювальних ресурсів.
